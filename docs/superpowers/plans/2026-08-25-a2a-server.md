# MAGI A2A Server Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a production-safe inbound A2A v1.0 server that projects MAGI decision cases as durable, tenant-scoped A2A tasks over HTTP+JSON and SSE.

**Architecture:** The official `a2a-go/v2` REST transport is mounted inside the existing Hertz process, while a custom `a2asrv.RequestHandler` projects MAGI's existing Case, Job, Event, Conversation, and Resolution records. MAGI remains the only execution state machine; new persistence is limited to A2A submission idempotency and durable per-case event sequencing. Reliability prerequisites are delivered before the feature flag exposes any A2A route.

**Tech Stack:** Go 1.25, `github.com/a2aproject/a2a-go/v2` v2.5.0, CloudWeGo Hertz (including its `github.com/cloudwego/hertz/pkg/common/adaptor` package), GORM, MySQL 8, SQLite tests, Atlas SQL migrations, Uber Fx, Prometheus text exposition.

---

## Delivery Boundaries

This plan implements inbound HTTP+JSON/REST and SSE only. It deliberately excludes A2A client behavior, JSON-RPC, gRPC, push notifications, file/image/audio input, extended agent cards, and an SDK task store. The official SDK is used for wire types, paths, error encoding, version negotiation, REST responses, and SSE framing; MAGI owns task identity, execution, recovery, cancellation, and results.

## File Structure

New files are split by one responsibility:

- `backend/application/a2a/types.go`: protocol-independent submission records, filters, snapshots, and repository interfaces used by the application package and DB adapter. All files in this directory use package name `a2aapp`, leaving `a2a` available for the official SDK import.
- `backend/application/a2a/input.go`: strict text/metadata parsing and canonical request hashing.
- `backend/application/a2a/cursor.go`: opaque keyset cursor encoding and validation.
- `backend/application/a2a/submission.go`: idempotent prepare/start/recover orchestration.
- `backend/application/a2a/projector.go`: Case/Job/Resolution to A2A Task state and deterministic artifacts.
- `backend/application/a2a/stream.go`: seq catch-up, live/DB merge, filtering, and A2A stream events.
- `backend/application/a2a/handler.go`: the eleven-method `a2asrv.RequestHandler` implementation.
- `backend/adapter/a2a_repository.go`: transactional submissions, owner-scoped task queries, and prepared-record recovery.
- `backend/server/a2a/transport.go`: Agent Card construction and Hertz/net-http mounting helpers.
- `backend/server/a2a/transport_test.go`: public card, auth propagation, base path, and feature-flag tests.
- `backend/server/a2a_integration_test.go`: official A2A client contract tests through the real transport.
- `docker/atlas/migrations/magi_s16_event_sequence.sql`: event sequence expand/backfill/contract migration.
- `docker/atlas/migrations/magi_s17_a2a_submission.sql`: A2A idempotency binding schema.

Existing files are modified only at their current ownership boundaries: entity/port definitions, GORM models/repositories, SSE replay, durable worker lifecycle, config/Fx/router wiring, metrics, nginx, and module dependencies.

func (r *eventRepo) ListAfterSeq(ctx context.Context, caseID string, afterSeq uint64, limit int) ([]*entity.MagiEvent, error) {
